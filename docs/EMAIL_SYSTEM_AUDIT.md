# Email System Audit Notes

## Active provider

Little Learner Hub now standardizes transactional mail on **Resend**.

Recommended sender:

- **Little Learner Hub <support@littlelearnershubbyleah.com>**

Why:

- best fit for password resets, support replies, admin notifications, and billing/help replies
- professional and trustworthy for transactional mail
- avoids the dead-end experience of `noreply@...`

## Render environment variables

Required:

- `RESEND_API_KEY`
- `SUPPORT_EMAIL_FROM=Little Learner Hub <support@littlelearnershubbyleah.com>`
- `SUPPORT_EMAIL_TO=support@littlelearnershubbyleah.com`
- `SITE_URL=https://www.littlelearnerhub.com` (or the final public app URL)

## DNS requirements for `littlelearnershubbyleah.com`

At minimum, Resend domain verification requires the exact DNS records shown in the Resend dashboard for the chosen sending domain/subdomain.

Typical records:

- SPF TXT record for the sending domain/subdomain
- DKIM TXT record(s) generated by Resend
- Resend MX record(s) required for bounce/complaint handling
- DMARC TXT record at `_dmarc.littlelearnershubbyleah.com`

Recommended DMARC starter record:

```txt
v=DMARC1; p=none; rua=mailto:support@littlelearnershubbyleah.com
```

After confirming SPF/DKIM pass in production, tighten policy gradually (`quarantine` then `reject`).

## Current public DNS audit snapshot

Observed during audit:

- `littlelearnershubbyleah.com` had Namecheap email-forwarding SPF
- a DKIM TXT existed at `resend._domainkey.littlelearnershubbyleah.com`
- **no DMARC TXT** was present at `_dmarc.littlelearnershubbyleah.com`

This means DNS still needs final verification against the exact Resend dashboard values before deliverability can be considered complete.
